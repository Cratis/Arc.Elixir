## Context

Decisions 0001 to 0007 proposed a family of packages, an Ecto integration and a Chronicle adapter that was second to Ecto. Building the first implementation, and the owner's direction that Arc for Elixir supports Chronicle only and that proxy generation is only for React and must be opt-in, changed several of those choices. This record states what was built and amends the earlier records where they differ.

## Decision

- **One package, `cratis_arc`, module namespace `Arc`.** It follows Chronicle.Elixir's single-package release flow (`Source/arc`, one `mix.exs`, one Hex publish). Phoenix, Phoenix.HTML and Phoenix.LiveView are optional dependencies, and the LiveView modules compile only when they are present. `Plug`, `WebSock` and `WebSockAdapter` are required. This replaces the package table in 0001; `arc_plug`, `arc_phoenix`, `arc_live_view`, `arc_chronicle` and `arc_test` exist as modules (`Arc.Plug`, `Arc.LiveView`, `Arc.Chronicle`, `Arc.Test`), not packages. Hex package name and module namespace, open in 0007, are resolved.
- **Chronicle only.** `cratis_chronicle` is a required dependency and the only persistence. There is no `arc_ecto` and no adapter for other stores. Reconsider only for a named consumer with a concrete requirement.
- **Handler results.** `handle/2` returns `{:append, events}`, `{:append, events, response}`, `{:ok, response}` or `{:error, results}`; `:ok` alone is not accepted. Arc appends returned events to the command's `key: true` field, or to an explicit `{event_source_id, event}`. This refines 0002.
- **Proxy generation is opt-in and Elixir-native.** `mix arc.gen.proxies` and the `:arc` Mix compiler generate TypeScript only when `arc: [application: …, output: …]` is set in `mix.exs`. The renderer follows the C# templates, emits inline `type` imports so output compiles under `verbatimModuleSyntax`, and uses the marker `// @generated by Cratis. Source: <module>. Hash: <sha256>` with no timestamp. This confirms 0003.
- **Contract gate.** `ContractTests/run.sh` proves determinism, strict compilation against pinned `@cratis/arc` packages and runtime behavior with the real client. A documentation verifier proves excerpts match sources.
- **Formatter export.** The package exports `locals_without_parens` for `field`, `authorize` and `response`, so `import_deps: [:cratis_arc]` keeps declarations free of parentheses.
- **No installer in this release.** The Igniter installer proposed in 0005 is not built; the documentation describes the few manual steps.
- **Observable transports.** Snapshot, direct Server-Sent Events, direct WebSocket and the WebSocket hub are served. The Server-Sent Events hub and delta transfer mode are not. This narrows 0004's transport statement. Subscription processes remain `restart: :temporary`.
- **Pipelines mirror Chronicle.Elixir.** Build on pull requests, publish to Hex through `cratis/release-action` on push to `main`, policy verification, nightly package updates, documentation trigger and artifact cleanup.

## Options considered

- **One package with optional dependencies (chosen).** One release stream and one version; matches the Chronicle client the package builds on.
- **The multi-package family of 0001.** Rejected for the first release: four additional release streams for modules that share a version and are small.
- **Keep an Ecto integration.** Rejected by the owner: Chronicle is the only supported persistence.

## Default if unanswered

The structure above stands. Splitting a package later is a breaking change for the module's users, so it needs a demonstrated need.

## Timeline and scope

Applies from the first release until superseded. Amends 0001 (package family), 0002 (handler results), 0004 (transports), 0005 (installer, package names), 0006 (Ecto no longer in scope; Chronicle is the only integration) and 0007 (milestones 7 and 8 collapse; naming resolved).

## Verification

- **Done when:** `mix test` for the package, `Samples/run-tests.sh`, `ContractTests/run.sh` and `python3 Documentation/verify-snippets.py` pass.
- **Verify by:** the `Build` workflow runs all four on every pull request.

## Consequences

Users get one dependency and one version. The package depends on Plug and WebSock even for a backend that never serves observables. Samples and documentation must be kept in step with the API, which the excerpt verifier enforces.
