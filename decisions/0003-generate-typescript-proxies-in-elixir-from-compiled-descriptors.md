> Confirmed by [0008](0008-ship-one-chronicle-only-package-with-opt-in-proxies.md): implemented as `mix arc.gen.proxies` and the `:arc` compiler.

## Context

Single-page applications consume generated proxies built on `@cratis/arc`. Arc.TypeScript parses source; Arc.Kotlin reads a compile-time manifest and renders in its own language. Elixir already has the full artifact metadata in compiled modules.

## Decision

- `mix arc.gen.proxies` reads descriptors from the compiled application (decision 0002) and renders TypeScript in Elixir. No Node.js is required to generate.
- A Mix compiler hook runs generation on development compiles, so proxies stay current as C# proxies do in a Debug build.
- Output is deterministic and carries the shared header, `// @generated by Cratis. Source: <name>. Hash: <sha256>`. A file without the marker is never overwritten, and stale cleanup deletes only marked files.
- The output targets the unchanged `@cratis/arc` and `@cratis/arc.react` packages. Existing `@cratis/arc.vite` plugins are reused.
- Scope follows the Arc.TypeScript rule: client-contract compatibility first, further mappings only for a demonstrated consumer need.
- Verification uses two gates. A contract test compiles generated output under strict TypeScript against the pinned client packages. A differential check compares output with a normalized .NET-derived fixture as a drift gate, not as a claim of byte-identical output.

## Options considered

- **Render in Elixir from descriptors (chosen).** No second toolchain, exact metadata, deterministic.
- **Reuse the Node.js generator.** Rejected: needs a source or manifest bridge and a Node.js build step on the backend.
- **Hand-written clients.** Rejected: loses end-to-end type safety.

## Default if unanswered

Generate on compile and on demand. The default output directory is set when the Phoenix installer is built.

## Timeline and scope

Implemented after the core pipeline and Plug host. Applies until superseded.

## Verification

- **Done when:** a sample application's generated proxies pass strict TypeScript compilation and a runtime check against a running Plug host.
- **Verify by:** run generation twice and compare hashes; run the TypeScript build and runtime contract suite.

## Consequences

Elixir users never need Node.js to generate. The Elixir renderer is another generator to keep aligned with the client packages and the shared header contract.
